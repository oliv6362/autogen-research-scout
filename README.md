# AutoGen Research Scout

Compulsory assignment for the **2026 Machine Learning course**.

A small AutoGen project that uses a local LLM and the OpenAlex API to search for academic research papers, apply constraints, and return a structured evidence-based answer.

The agent can handle requests with:
- Research topic
- Publication year constraints
    - Before, after, and exact year comparisons
- Citation constraints
    - Minimum, maximum, and approximate citation counts
- Cases where no valid paper can be found

## Evaluation Results
- [Evaluation outputs](https://github.com/oliv6362/autogen-research-scout/blob/master/results/evaluation_outputs.md)

## Tools

The project uses one external research-paper tool:

- **OpenAlex Tool:** Searches OpenAlex for academic papers and returns metadata such as title, authors, publication year, citation count, URL, DOI, venue, and abstract.

Citation counts are taken from OpenAlex and are not generated by the LLM.

## Architecture

The project is split into small modules:

- **agent.py:** Creates the AutoGen research agent and user proxy, and registers the research-paper tool.
- **openalex_tool.py:** Calls the OpenAlex API and maps raw API results into internal Paper objects.
- **research_tools.py:** Exposes the AutoGen-facing tool function.
- **workflow.py:** Performs deterministic filtering by publication year, citation count, and required metadata.
- **models.py:** Defines shared data models such as Paper, SearchConstraints, SearchResult, and EvaluationResult.
- **test_prompts.py**: Contains the evaluation prompt set.
- **evaluator.py**: Runs the agent against the evaluation prompts and saves the outputs.

The LLM is responsible for understanding the user request, extracting constraints, calling the tool, and writing the final explanation.

The deterministic Python workflow is responsible for enforcing publication year and citation-count constraints.

## Prerequisites

- Make sure Ollama is running locally and that you have pulled an Ollama model, for example gemma4:latest.
- The project was developed using Python 3.12 in a Miniconda3 environment.

## Installation

Import a virtual conda environment from YML from the project root folder:

    conda env create --file environment.yml
    
Activate a virtual conda environment:

    conda activate AutoGenResearchScout

If necessary, how to remove a virtual conda environment:

    conda env remove -n AutoGenResearchScout
    

## Configuration

Create a local configuration file:

    src/research_agent/config.py


Example local Ollama configuration:

    LLM_CONFIG = {
        "config_list": [
            {
                "model": "gemma4:latest",
                "api_type": "ollama",
                "client_host": "http://127.0.0.1:11434",
                "temperature": 0.0,
                "seed": 42,
                "stream": False,
                "native_tool_calls": False,
                "cache_seed": None,
            }
        ]
    }

## Evaluation

### The agent was evaluated using 10 prompts covering:
- Broad topics
- Narrow topics
- Before, after, and exact year constraints
- Minimum, maximum, and approximate citation constraints
- Ambiguous requests
- Expected failure cases

### The evaluation checks whether the agent:
- Finds a relevant paper
- Respects the year constraint
- Respects the citation constraint
- Provides a valid source
- Avoids hallucinated information
- Gives a useful explanation

Most prompts were handled successfully. The main limitation was topical relevance in one transformer-related prompt, where OpenAlex returned a numerically valid but topically weak result.

## Reflection

### What worked well:
- The agent successfully used OpenAlex instead of relying on the LLM’s internal knowledge.
- Publication year and citation-count constraints were enforced with deterministic Python code.
- The agent could reject unrealistic requests when no valid paper was found.

### What was unreliable:
- The system message had to be very specific before the local LLM used the tool correctly. Early versions used invalid operator values or waited for more input instead of calling the tool.
- The LLM sometimes failed to end with TERMINATE or wrote a broad analysis instead of selecting one valid paper.
- When the tool returned several valid papers, the LLM could become distracted by too much information.
- In one case, the LLM set the search limit to 1, which reduced the chance of finding a good result. This was fixed by enforcing a minimum search limit in the tool.

### Failure case:
One limitation was observed in the test prompt: *“Find a paper about transformer neural networks published before 2018 with more than 10000 citations.”*

The OpenAlex tool returned *“Gradient-based learning applied to document recognition,”* likely because the abstract contains the phrase “graph transformer networks.” Although the returned paper satisfied the publication year and citation-count constraints, it was not directly related to the modern attention-based Transformer architecture.
  
This indicates that the deterministic filtering layer is effective for numeric constraints, but that topical relevance remains dependent on retrieval quality and the ambiguity of the search query.

### Possible future improvements:
- Improve exact-year constraint extraction.
- Add relevance validation step before accepting a paper.
- Add a second source for verification.
- Improve the evaluation with automated scoring.
